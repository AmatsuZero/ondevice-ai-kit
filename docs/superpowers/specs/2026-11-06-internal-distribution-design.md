# 内部闭源使用与分发

## 目标与范围

项目自身代码提供内部使用、修改及组织内部源代码/二进制分发许可；不授予公开发布或向组织外分发的许可。
不推定雇主或著作权人名称，不改变第三方代码、模型、素材原有许可，也不宣称有权将其闭源重许可。
本许可不是生产质量或发布批准；既有 review、校准、P4/P11 门槛继续保留。

## 方案

对比过内部闭源、MIT 与 Apache-2.0；用户选择内部闭源。根目录 `LICENSE` 为项目特定条款，
README 指向该条款；不使用 MIT/Apache 名称描述项目自身代码。

工程上选择从精确提交的源码快照复制项目 LICENSE。直接读取打包时的工作树 LICENSE 会把后来的决定
混入旧提交，因此不采用。快照将根 LICENSE 作为 `packages/LICENSE` 登记字节及 SHA256，
打包器从快照复制到 `notices/ondevice-ai-kit/LICENSE` 并在 SDK attribution 中指向它。
没有 LICENSE 的历史提交继续标明许可未确定、仅本地验证；不回写旧快照或制品。

## 验证与停止点

先用真实 Git 提交验证 LICENSE 按提交取值、不使用 dirty 工作树；验证 notices 保留原始第三方文本、
项目许可字节及哈希，历史无许可快照不被自动提升。沿用完整工具回归。
只提交本地文件，既有原生制品不重建、不覆盖、不发布；生产分发渠道与独立审查仍待后续裁定。
