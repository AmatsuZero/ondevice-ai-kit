# 参考音色变声设计

## 意图

在现有离线变声 Demo 中增加“参考音色”模式：用户录制或导入一段目标说话人的语音，再录制或导入另一段内容语音，Demo 在本机使用 OpenVoice ONNX 将内容语音转换为参考说话人的音色，支持试听和导出。当前低延迟实时角色音效继续保留，两个能力在界面上明确区分。

## 目标

- 参考音频和内容音频都支持录音、导入 WAV、试听。
- 参考音色转换在 iOS 和 Android 复用现有 OpenVoice 模型与本地处理链路。
- 转换结果可试听、导出；页面离开时清理临时输入、目标 embedding 和输出。
- 没有参考音频时，现有固定音色 A/B/C、升调、降调和实时角色音效继续工作。
- 参考音色仅作为当前任务的临时数据，不上传、不写入固定 Demo 资源。

## 不在本次范围

- 实时参考音色克隆或通话级低延迟神经变声。
- 多说话人分离、音色库管理、账号同步、云端处理。
- 明星或未经授权的声音身份复制宣传。
- 修改已有固定音色的模型资源和实时 DSP 算法。

## 方案

### 方案 A：在现有 OpenVoice C++ 链路中增加参考音频编码（采用）

新增“提取目标 embedding”入口：复用现有 STFT 和 `ref_encoder.onnx`，将参考 WAV 转为 256 维向量；转换入口接收内容 WAV 与目标 embedding，再调用现有 `converter.onnx`。共享 Kotlin 状态只增加参考输入的生命周期和自定义目标选项，iOS/Android 宿主分别增加录音/导入参考音频的入口。

优点是复用已验证的模型、资源和内存限制，固定音色与参考音色共用转换器；缺点是每次任务增加一次 encoder 推理，结果仍是文件模式并有明显等待时间。

### 方案 B：把参考 embedding 先导出成用户可管理的音色文件

首次录音后单独生成并保存 `.f32` 音色文件，后续转换只执行 converter。

优点是重复使用同一参考音色时更快；缺点是需要新的文件格式、导入导出和生命周期安全策略，容易把临时音色变成长期隐私数据。本次先不做，后续有音色库需求再拆分。

### 方案 C：采用新的流式神经变声模型

换用支持短窗口流式处理的模型，直接做实时参考音色克隆。

优点是最终延迟目标更好；缺点是模型、运行时、内存和双端适配都需要重新验证，不能复用当前 OpenVoice 的文件转换验收。本次不采用。

## 交互

文件变声页增加“参考音色”卡片：

- “录制参考音色”与“导入参考 WAV”二选一，显示时长和名称。
- 参考音频可单独试听、清除；录音建议 5–30 秒，少于 0.5 秒拒绝。
- 现有“输入音频”卡片作为要转换的内容，继续支持内置示例、录音和导入。
- 选中“自定义参考音色”后，点击“转换为参考音色”；转换完成显示 ONNX Runtime 后端和输出参数。
- 实时变声 tab 继续展示低延迟 DSP 角色，不与参考音色转换混用。

## 实现边界

- 共享层：扩展 `DemoVoiceTimbres` 和 `VoiceEffectsViewModel`，增加 reference input 的注册、持有、释放、取消和关闭清理；不改变固定音色调用路径。
- C++：将参考音频的 canonical WAV 解析、STFT、encoder 推理抽成可复用函数；新增 `openvoice_render_reference` 宿主入口；embedding 只在单次转换的内存中持有，不写入文件。
- iOS：在 `VoiceEffectsHost` 复用现有 `AVAudioRecorder` 生命周期，增加参考录音状态和 `OpenVoiceTimbres` 的 custom target 调用；继续沿用现有 Core ML/CPU backend 标记。
- Android：在 `VoiceEffectsHost` 增加参考输入文件持有；`OpenVoiceAudio` 和 JNI 增加 custom target 调用；继续使用现有按 ABI 的 ONNX Runtime。
- 原型：同步增加参考音色录音/导入与转换入口，但原型只用于交互确认，不替代双端模型验收。

## 验收

- 参考音频和内容音频来自两段不同录音时，转换结果不是原内容的字节拷贝，能在本地播放器中听出参考音色特征。
- 同一参考音频重复转换得到稳定结果；取消、换输入、离开页面后临时文件和 embedding 均释放。
- iOS 真机和 Android 设备至少各完成一次“录参考 → 录内容 → 转换 → 试听/导出”。
- 固定音色 A/B/C、升降调和实时角色回归测试继续通过。
- 记录模型后端、输入时长、输出采样率、转换耗时和未测的主观听感边界。

## 实现补充（2026-11-28）

- 按已确认原型提供 01 参考音频、02 内容音频、03 结果对比三张卡片，导入、录制和清空按钮统一高度与等分宽度。
- 波形来自实际 PCM 的 128 个峰值区间；原声与结果共用时间长度和 −60 至 0 dBFS 标尺，支持点击、拖动定位及播放进度线。
- 自定义参考音色使用 ONNX Runtime CPU；固定 A/B/C 继续保留原有 CPU/Core ML 选择，实时角色继续使用现有 DSP。
- 开发与模拟器验证记录见 `docs/validation/reference-voice-demo-20261128.md`。真机录音、实际耳机听感与 iOS 系统保存仍作为独立验收项。

## 需要用户确认的选择

本设计默认采用方案 A，只做“录完再转换、试听/导出”的文件模式；参考音色只在当前页面临时有效，不保存为长期音色库。
