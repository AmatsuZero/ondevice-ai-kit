# KMP Multimodal host/VM real-device lifecycle design

Goal: prove the actual KMP MultimodalViewModel→IOSMultimodalBridge→SDK→fixed MLXVLM lifecycle on the authorized physical iPhone, after ab40fec optional host composition. This package is a separate validation consumer, not touch UI/picker acceptance. Existing shared screen uses this same VM; actual shared Compose rendering/navigation remains a separate unverified gate. No KMP header/export change is needed.

A fresh generated iOS18 validation App (bundle io.ondeviceai.multimodallifecycle) links the existing ODAIKitDemo framework plus base/apple-mlx products and exact lock. It compiles actual MultimodalHost/InputStore/bridge sources and a test-only Swift suite. Alternative enhanced-Demo debug hooks would add validation behavior to product flows; UI automation would hit an already documented external initialization gate. A separate consumer keeps production unchanged and provides deterministic first delivered update interception, at the cost of leaving page rendering unverified.

The suite installs canonical Documents/model into its own Documents/lifecycle-model-store, acquires a real lease, creates MLXVLMBackend/client/IOS bridge, and passes a forwarding observation bridge to actual MultimodalHost/VM. It injects only the public synthetic Documents/fixture.png picker reply. Forwarding observation never replaces runtime output: updates/results/errors pass unchanged to the VM, and records sequence/phase/identity plus input lease acquire/release. At first delivered update it invokes VM.cancel, host.background or host.close as the scenario requires. Every terminal must follow input release, and real client.drain is awaited. Query availability is real. All waits bounded; failure records a fixed gate label, never raw paths or arbitrary errors.

Scenarios in one PID/runId: actual available backend; successful fixed-image output with at least one delivered update and exact model/backend/runtime identity; cancellation triggered synchronously after first delivered update, VM CANCELLING then CANCELLED, no output; immediate same-process reentry succeeds; background cancels after update, foreground does not generate automatically (bounded idle observation and forwarded generation counter); active close after update joins drain, releases input and model lease, clears owned temporary input directory, repeated close is idempotent, VM and bridge reject generation after close. ModelStore.remove must reject while leased and succeed after close; only the suite's own installed model is removed, canonical source preserved.

Raw JSON includes schemaVersion1, sourceCommit, runId, pid, physical/simulator marker, OS, fixture SHA256, exact identity, explicit per-scenario pass booleans and ordered trace events. Host-side validator rejects missing/false/type-confused gates, wrong identities/hash/platform/source, missing first-update ordering/release-before-terminal, false success or absent evidence. It does not report latency/RSS/quality. Existing asset hashes verified before copy; no network/download/private media/audio or signing changes. Only existing authorized team/profile and device. Missing assets/device/authority are accurately unverified; no repeated retry of known external UI gate.
