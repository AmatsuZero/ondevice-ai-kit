## W9 产品合同

1. 用户可从文件导入或在 Demo 前台录一段音频，结束后处理，再对比原声/变声并导出 WAV。
2. 首版预设为原声、高音、低音；不将升降调宣传为自然男女声转换。预设数值和支持格式在 W9-0 的合同产物中冻结。
3. 无实时监听、通话插件、指定人物音色克隆、神经语音转换或新模型训练。变声不经 ASR→TTS，不依赖 Google 识别资源。
4. SDK 为独立的 audio→audio 能力，不复用 ASR 结果类型；复用既有文件 lease、可用性、busy、取消/drain/close 和错误映射模式。录音采集由宿主控制，文件转换可独立于麦克风运行。
5. 输出与输入分离，取消/失败不发布半成品、不改调用方输入；关闭后拒绝新请求，释放后才允许占用同一音频资源。
6. 默认仅离线本地处理；Demo 提供实际后端、支持范围和失败原因。录音权限只在录音入口需要；导入、转换和导出不强行索取麦克风权限。

### 主代理提出的工程边界，需先验证再冻结

- 优先支持单声道 PCM16 WAV、16/44.1/48 kHz、最长 30 秒；录音统一导出到同一入口格式。其他格式/超限明确拒绝。
- 原声为 bypass，高音/低音候选为 +4/-4 半音，目标保持时长；不得仅改变播放速度后冒称保时长变声。
- 先用合成音验证实际输出的频率和时长，再核人声可懂度、截断/爆音、前后静音和连续拼接。30 秒、半音数、误差界限属于待冻结的工程提议，不是已有用户数值验收批准。
- Android 当前未找到已接入的 Sonic/Media3/SoundTouch 变声引擎；Apple 当前也无变声 SDK。平台 API 存在不等于双端文件渲染已实现。W9-0 必须先交付两端可行性结果，禁止把两个后端实现都直接标成可交付。
- 优先平台现有能力与仓库已有组件；新增第三方依赖须另行明确授权，不预设可添加 Media3/SoundTouch，也不为期限静默降级效果。

本周候选须绑定源码/模型/依赖/构建配置与输入；双端 SDK 消费、Demo 实际录音/导入/转换/试听/导出、取消/关闭/重入、前后台/中断以及失败清理有真实结果。适用资源预算在测量前冻结；现有观测不能反推通过线。缺失的真机、最低系统、质量或能耗结果分别记录，不能用构建或模拟器替代。

低系统实体设备沿用既有延期，不扩张为所有设备通过。W9 新录音只在用户明确进入录音动作后开始；本次更新计划不授权代理自动开麦、采集新私人媒体或改签名资产。

如双端可行性、必要通知或候选验收未通过，日期仍是目标，交付状态保持 blocked/not-ready，并列出具体阻断；禁止把“文档齐全”当作验收完成。
