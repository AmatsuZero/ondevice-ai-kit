# 能力详情页设计草稿

2026-11-22；状态：用户已确认（“设计稿没问题”），进入正式实施。沿用已批准的统一浅底、绿色强调、KMP + CMP 页面与原生媒体 Host 边界。本目录为一次性可点击设计原型，不是正式 App 构建输入；不读取媒体、不运行 SDK、不访问相机或麦克风，不生成文件或保存真实记录。

## 当前问题及证据

- 用户提供的文件超分、播放增强两张真机截图中，状态栏下面仍有大块留白；页面底部出现不同底色的安全区。
- `demo/iosApp/OnDeviceAIDemoApp.swift` 的根 `VStack` 默认遵守 SwiftUI 安全区，没有让 shared 根视图延伸至全屏。
- `demo/shared/src/commonMain/kotlin/io/ondeviceai/demo/UnifiedDemoScreen.kt` 使用默认 `Scaffold`，又对整列应用返回的 `padding`。CMP 会映射 iOS 安全区，这形成重复处理的高度嫌疑，与截图在安全区之后额外留出近一份安全区高度相符。尚未修改产品代码或测量修复后的真机坐标，不能把源码推断当运行验证。
- `PageHeader` 额外增加 12dp 顶部 padding，并用 `Spacer(Modifier.padding(32.dp))` 平衡两侧；后者同时增加竖向尺寸。标题行没有设置居中垂直对齐。它不是尺寸受控的导航栏。
- `CapabilityPage` 固定放置目的说明、保存按钮，然后嵌入旧 `VideoScreen` / `PlaybackEnhancementPage`；旧页面又包含标题、说明、原始后端标识和状态，形成信息重复。
- `UnifiedDemoTheme` 没有覆盖所有 Material3 容器色，`Card` 仍可能使用默认色阶；截图中的紫色卡片与绿色主题不一致。
- iOS 媒体容器在 `MainViewController.kt` 固定 360dp 高，Android 接入也有各自尺寸；应改为共享页面约束的媒体比例，并在两端验证原生渲染视图尺寸。此原型展示 16:9，不替代 SDK/画质测试。

官方参考：Material3 文档说明 Scaffold 提供的 insets 应由内容使用，避免再叠加其他处理；Kotlin 文档说明 CMP 在 iOS 上也映射安全区。当前 Context7 工具未提供，使用官方文档检索核对：

- https://developer.android.com/develop/ui/compose/system/material-insets
- https://kotlinlang.org/docs/multiplatform/compose-platform-specifics.html
- https://kotlinlang.org/docs/multiplatform/compose-swiftui-integration.html

## 方案与建议

1. 只修安全区和导航高度：改动小，能恢复内容面积，但仍保留旧能力面板的重复标题与调试信息。
2. 修复公共容器并整理所有能力详情模板（建议）：保留现有 ViewModel / Host，让主要体验按输入、设置、运行、结果组织；高级技术信息折叠。先用这两页确认，再映射到其他能力。

本原型演示方案 2，用户已确认采用；正式实施与验证按对应计划执行。

## 原型约定

- 同一绿色主题、字号、白色分组卡片、边距；52pt 导航内容高度为设计初值，正式实现须支持文字放大，不能硬裁标题。
- 页面背景延伸至系统状态栏与 Home 指示区域，内容和操作只避让一次；不靠写死机型顶部/底部数值消除空白。横屏、无 Home 指示条设备和键盘需独立验证。
- 输入限制保留在主要流程，不藏起导致用户无法选片；后端 ID、刷新、严格选择、资源详情、原始错误收进高级信息。
- 文件超分：输入卡片 → 输出和音轨设置 → 底部运行/取消 → 结果内查看、导出、保存。只有已有结果时展示保存记录；不删除音轨选项、清理和失败恢复能力。
- 播放增强：16:9 媒体空态/原生预览 → 文件概要 → 模式 → 实际呈现；选择与实际上屏区分，未播放显示“尚未播放”。增强超时或失败继续原画并解释原因，不伪造增强结果。
- 文件超分现有 Apple 后端仍限 iOS 26+ 支持设备、320×180 / 24fps / 1–48 帧 / BT.709 SDR、4× 输出。重新设计不扩展处理能力。
- 现有记录仅当前进程摘要，不能让设计改变为持有媒体/输出 lease 或持久保存。输出显式清理及离页释放仍要保留。
- 取消沿用现有 native drain / 清理完成后的再启用，不能为视觉反馈提前释放或重新开始。
- 冻结能力仍只预览，权限、缺模型、未接入、设备不支持、运行失败分别解释；错误修复入口不能全部折叠隐藏。

## 原型覆盖与边界

`index.html` 包含文件选择示意、处理/取消/结果、音轨设置、高级后端选项，以及播放选择/暂停/模式/原画回退示意；右侧提供重置、无效输入、后端不可用、播放回退布局入口。所有页面有醒目的模拟说明；不以合成图宣称实际增强。

浏览器控制返回 `The browser access host is unavailable`，原生 Safari 捕捉返回 `SCStreamErrorDomain Code=-3811`，因此本轮没有真实浏览器视觉或可点击操作验收。脚本语法和非浏览器 DOM 状态检查分别记录；不能替代浏览器或双端 App 检查。

本轮 `node --check` 通过，29 个静态元素 ID 无重复，18 项非浏览器 mock DOM 回调检查通过（输入/取消后无迟到完成/结果/记录仅模拟/异常输入/后端不可用/严格选择/播放与回退）；收据在 `/private/tmp/odai-detail-design-20261122/`。本机 HTTP 200 且服务内容与原型字节一致。未运行正式 App 构建或 SDK 测试，因为产品文件未改。

原生只读复核已完成，结论为“无 blocker，可作为待确认原型继续讨论”；原件为 `/private/tmp/odai-detail-design-20261122/native-design-review.md`。正式实施须先修正 PageHeader 的竖向占位，再验证安全区；播放模式继续读取真实 `supportedModes`，实际呈现继续读取 `presentedMode`，不固化原型的示意选项。用户确认继续原型收尾后，再次尝试打开本机预览仍返回浏览器 host 不可用；不能称页面已自动打开。

## 确认后实施与验收

1. 先在默认 App 捕获旧布局，记录真实安全区、导航边界、预览区大小；再统一 insets 所属与背景，公共导航和滚动区共同消费已应用边距。
2. 保留独立相机/方向探针和旧工厂接口；核 root 下既有 message / report / 权限设置等 SwiftUI 辅助内容，避免直接全局忽略安全区导致遮挡。
3. 以共享详情组件整理正式页面，复用能力的现有状态与动作；媒体帧/文件/平台对象仍归 Host，不改算法或 SDK 协议。其余语音、人脸、图像、模型与记录详情沿用同一导航和信息层级。
4. 核心回归：输入替换、取消等待、失败重试、严格后端选择、资源清理、离页/后台、记录、选片器取消；检查 375 宽、横屏、文字放大和键盘遮挡。
5. Android/iOS 默认 App 编译与适用回归，通过运行坐标/截图确认顶部无重复安全区、底部背景一致、导航文字无裁切、主要操作可达；原生视频嵌入按实际布局尺寸验证。原型可点不等于产品已修复。
