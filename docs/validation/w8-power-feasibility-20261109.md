# W8 Apple Power Profiler feasibility — bounded idle window

On 2026-11-09, one exact-PID Power Profiler recording and its two data-table exports succeeded on the connected iPhone with Xcode 27.2 (27B52), iOS 27.2. This removes the previous blanket assumption that the tool currently cannot produce an export. **It does not accept any capability's workload energy or resource budget.**

The signed, isolated TTS probe was launched without pressing its run button: no speech, model inference, microphone or camera operation. `xctrace` attached to PID 6947 in the new alias `io.ondeviceai.probe.w8tts20261109`. Its requested 20-second recording ran from 11:09:59.254 to 11:10:20.941 +08; the TOC reports 21.686627 seconds, `Time limit reached`, the same PID and installed executable path. Recording, TOC export and both data exports returned zero.

`ProcessSubsystemPowerImpact` contains 41 rows; `SystemPowerLevel` contains 22 rows. These are instrument-modeled impact/system-level fields, not a validated joule or watt measurement. Some raw fields contain negative near-zero or zero values; their semantics and completeness have not been accepted for workload comparison. Table presence alone is not an energy-quality pass. A future capability-specific run must freeze the workload/window and validate usable metric semantics, attribution and budget separately.

The original 2026-10-27 failed All Processes attempt and target-process `NetworkConnectionStatsModeling.receive` SIGTRAP remain historical evidence. This new check changed the target workload and used the current toolchain/OS; it does not identify which change resolved that failure or establish reliability for other workloads.

The parent's initial launch wrapper put `--device` after the variadic App-argument position. `devicectl` rejected it with exit64 before launch/recording. Its temporary alias was removed; raw errors remain at the evidence root. The corrected command placed device options before the bundle identifier, with new raw files under `launch-corrected/`. Only that corrected attempt made a recording. No tool-crash retry loop was used.

After export, only the new alias was uninstalled. All 44 original installed-App records matched exactly, and a fresh mobile foreground query confirmed the original Combined App. Unique traces, exports and errors are retained. No new build cache was generated by this task, so the task cleanup check removed nothing.
