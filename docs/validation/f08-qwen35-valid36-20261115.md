# F08 Qwen3.5-2B 4-bit valid36 disposition (2026-11-15)

## 结论

Qwen3.5 首次运行的 `SIGTRAP / EXC_BREAKPOINT` 已定位并在隔离 runtime 中用最小两行修复消除。新的 Mac MLX Metal valid36 完成 **36/36**，独立重算 **72/72** 个完整 logits（含 EOS）通过，但严格成绩只有 **17/36**，相对 Qwen3 基线 `16/36` 仅 **+1**。预注册门要求 `>=20/36` 且净增 `>=+4`，因此本候选不进入 iPhone 评估，W6 继续 `open/not-ready`。

## 阻塞根因

首次完整运行在模型加载后进入第一题，exit `-5`、完成题数 `0`。单题阶段探针证明以下阶段均已成功：

- checkpoint 加载；
- 8 帧读取与 processor；
- token、pixel SHA、外层三轴 position 与 rope delta；
- vision tower forward；
- 576 个视觉特征与 576 个视频 token 的合并。

最后成功 marker 是 `runtime-31-continuation-vision-completed`。随后在 `Qwen35.prepareContinuation` 内调用 `Qwen3VLLanguage.getRopeIndex` 时触发 Swift trap。

`Qwen35` 的两处共享 RoPE 调用都漏传 `config.visionEndTokenId`，因而使用 Qwen3 默认值 `151653`。本 checkpoint 的真实 vision-end token 是 `248054`；第一题 token 中有 4 个 `248054`，没有 `151653`。隔离视频 position 合同找不到错误的 end token 后执行 `preconditionFailure`，表现为 `SIGTRAP`。

最小修复仅在两处调用增加：

```swift
visionEndTokenId: config.visionEndTokenId,
```

同一第一题红绿结果：修复前 exit `-5`；修复后 exit `0`，logits shape `[1, 1, 248320]`，完整进入终态 `completed`。

## 混合缓存验收订正

原 probe 还错误要求 24 层 cache 的 offset 全部等于 token 数。Qwen3.5 实际是 18 个 `linear_attention` + 6 个 `full_attention`：

- `full_attention` cache 维护 token offset；第一题 prefill 后为 `679`；
- `linear_attention` 使用 `MambaCache`，以两个 recurrent-state 数组判定已经推进，metadata offset 保持 `0`。

这与 pinned runtime 的 `ArraysCache.advance` 合同及 `CachedForwardSmokeTests` 一致。新的 probe 与独立 verifier 分别检查注意力 offset 和 Mamba state，不再把正确的混合缓存误判为失败。

## valid36 结果

唯一新的完整 Mac Metal 进程：

- exit `0`，36/36 完成；
- 严格正确 `17/36`，invalid `0`；
- 相对 Qwen3：both correct `10`、Qwen3.5 only `7`、Qwen3 only `6`、both wrong `13`；
- 分类：counterfactual `3/6`、memory `2/6`、abstraction `1/6`、physics `3/6`、semantics `3/6`、camera motion `5/6`；
- 独立 verifier 重读 72 个 float32 logits、token 选择、EOS、rope delta、输入合同及混合 cache，全部通过；
- 模型循环 `16.448s`；Mac 峰 physical footprint `3,784,232,104 B`（约 `3.524 GiB`），峰 MLX `2,721,266,819 B`（约 `2.534 GiB`）。这些是 Mac 实验观测，不是 iPhone 产品预算。

## 处置

运行时崩溃阻塞已经解决，模型质量门仍失败。Qwen3.5 只比 Qwen3 多答对 1 题，且 abstraction 仅 `1/6`、memory `2/6`；没有足够依据承担 iPhone 下载、加载、内存和持续热评估成本。本分支停止于 Mac，不操作 iPhone，不改 App/SDK 默认模型。

W6 当前仍未完成。后续若继续通用短视频理解，需要新的独立质量依据，例如任务收窄、专门训练/微调，或同时具备移动资源与 held-out 质量理由的新模型；继续在现有 2B 通用候选上做 prompt/路由扫描没有达到既定门。
