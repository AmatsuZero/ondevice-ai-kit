# Qwen 两阶段候选：事前执行合同

目的：保留请求语言的转写质量，同时用自动语言解码判别非语音；不再使用会漏掉
AMI C-294 的 VAD 准入器。此处是主代理的候选设计，不是已通过的生产方案。
依据为[自动语言实测](w3-qwen-auto-language-observed-20261110.md)。

固定模型/运行时/解码参数沿用[原设计](../superpowers/specs/2026-11-10-w3-asr-reselection-design.md)。
唯一新行为：

1. fresh stream、`language=""`，解码完整原幅度 PCM。
2. 只在原始输出严格等于空字符串时拒绝，最终文本为空；不 trim、改写输出或设置信度阈值。
3. 有任何文本则 fresh stream、按 locale 设置 Chinese/English，再解码同一完整数组；
   最终输出为第二次原文。不得复用先前实验的 hypothesis 伪装为本批调用。
4. 准入报告与实际 decode 调用计数在第二次 native 调用前持久化。首/次解码失败记录
   原异常，不能当成无语音成功；每片结束才清零样本，Python GC不冒充native析构确认。

先用 fake runtime 验收准入拒绝、两种 locale、原样输入、真实调用计数、两阶段异常与
第二调用前报告可见性。保留原15组协议/错误检查。实现由免费 CBC 候选提供，父精确集成。

只执行一次固定开发批次：原9语音、原2全零、原2固定噪声，共13条，最多22次decode。
9条语音须全部成功、非空且通过准入；中文原CER<=25%，近场英文原WER<=25%，
AMI原WER<=50%且每片<100%；4非语音均必须在第一次解码后返回空文本且不进入第二次。
原 scorer/NFC/casefold/标点数字规则不变。协议/源码/模型/PCM摘要在native前冻结。
每片完整两阶段耗时<=120s，进程RSS<=4GiB是Mac保护条件；任何失败停止此配置，不扫参。

开发批次通过才进入独立质量集：FLEURS中英文各20片（排除全部开发ID）、另一个AMI会议12段；
选片只按固定reference/时间规则，不能依结果换样本。中文CER<=20%、近场英文WER<=20%、
远场英文WER<=35%，语音全成功，另设冻结的非语音挑战。手机目标与适用预算仍依原设计，
必须测完整两阶段，不能把旧tiny或单次Qwen时延当新管线成本。

无生产替换、麦克风、AiAi请求或默认网络/服务修改。W3仍open，原失败完整保留。
