两个 ZIP 实际摘要同时匹配本次 API 和原官方 job 上传/下载日志；本次还重新读取官方 Release asset `678742021` 的摘要、逐行核对原 50 条日志摘录。它们比较各自相同容器，不把 ZIP 摘要拿来与 AAR/SO 摘要混比。[原出处记录](w3-runtime-official-provenance-20261111.md)的历史边界保留。

CI libs ZIP 含四 ABI 的 16 份 SO 和四份使用说明；逐成员路径/尺寸/SHA 先与原 AAR 清单核对，再比较实际解压字节，且无多出或漏掉的 SO。两套读取对整份 AAR 和 16 库均一致；第二实现采用已实测身份的 `/usr/bin/unzip`，不是仅由命令名推定。

首次两个下载各在父包装器 180 秒时限结束，随后精确 `206` 续传又在 900 秒时限结束，均有持续收到的字节。确认旧文件无打开进程、保留原 partial/失败 range 及摘要后，只续取最后 2,643,079 / 9,942,968 B；最终完整长度与官方摘要通过才接受。没有重传完整工件、改全局代理或抹去失败；首异常 traceback 在工具记录中，未单独重定向到磁盘，相关观察收据明确此限制。

免费 hy3 源码复核后交付五处最小替换；固定长度/摘要与绝对 Info-ZIP 路径已逐块原样集成。首 JSON 提取器因结果含前导文字失败，原输出保留，随后只提取其中唯一合法 JSON block；不是 CLI/配额失败。第三条“未比较 API 摘要”意见未单独采纳，因为原源码已直接比较 API 摘要，原日志摘要是附加核对；父裁定保留这一更正。
