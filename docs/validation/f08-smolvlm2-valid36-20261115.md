# F08 SmolVLM2 2.2B valid36 host Metal comparison

状态：**完成本候选的主机筛选，未进入 iPhone 36 题；F08/W6 仍为 open/not-ready。**

## 结论

复用已冻结的 Perception Test `valid36` 选择、同一组 36×8 PNG 帧、实际时间、原问题/选项和严格单字母评分，为 SmolVLM2 2.2B 4-bit 独立生成原生 384px/81-token 输入。唯一 MLX Metal 进程完成 36/36：

- SmolVLM2：**14/36**，invalid **1**。
- 已有 Qwen3-VL：**16/36**，invalid **0**。
- 逐题：两者都对 9、仅 Smol 对 5、仅 Qwen3 对 7、两者都错 15；净值 `5 - 7 = -2`。
- 预注册晋级条件是 Smol 至少 20/36，且净值至少 +4；两项均失败，`advanceToIPhone36=false`。

因此，SmolVLM2 2.2B 在此前 fixed24、valid18、expanded72 的优势没有在这批独立 valid36 上延续。当前证据不支持为它再做一轮 36 题 iPhone 资源和热验收，也不支持替换 Qwen3 或改生产默认。

逐类配对中，反事实有 1 条 Smol-only、相机运动有 2 条 Smol-only 和 2 条 Qwen-only；记忆/物理各有 1 条 Qwen-only；语义有 2 条 Smol-only、3 条 Qwen-only。抽象类 6 条全部两者都错，继续显示细粒度计数、字母/序列和抽象判断仍是共同阻塞。

唯一无效输出来自 `pt-valid36-video_10383-q6`：模型生成 `A. All the letters match, but the order is not the same.`，期望 B。其余失败均为合法单字母选错。输出分布为 A 14、B 14、C 7、invalid 1，没有单一字母塌缩。

- 选择文件 SHA-256：`ffe451c7ef0f32f898d5a8602901c111820e6e2adb3a544546f42cb84621e00c`。
- 导出帧元数据 SHA-256：`5da484882c6b672c59ee2fc117cbd97786b5f6d53d232c2a80db370f1810e0ac`。
- 模型 revision：`0a4ab666f99095e6c6bd0e1e49aca8822fc46df2`；权重 SHA-256 `dbdf6ff7b0e7e160f3b135c15c3afbe9580214747e62967585b417d966cade37`。
- 288 帧全部从既有 valid36 证据读取；没有复制视频、下载权重/数据或重新解码媒体。
- HDTV ICC 显式转 sRGB；独立 Pillow/LittleCMS 公式逐元素重算 36 组 `[1,8,3,384,384]` FP32 数组。
- 36 份模板逐 token 重建；每帧 81 个图像 token，共 648 个。
- fresh 24-layer KV、balanced512、greedy32、EOS 49279；保存并复算 86 份完整 FP32 logits（含 EOS）、所有 argmax 和 layer offsets。
- 唯一进程使用 `Device(gpu, 0)`；Torch/Torchvision 不存在，未运行 CPU 模型、Ollama 推理或手机 App。

## 资源观察

- 36 题模型循环耗时 20.826 秒；单题中位 0.544 秒。该时间不含此前输入准备，也没有单独记录模型加载耗时。
- MLX 进程内峰值 `2,608,255,518 B`，约 **2.429 GiB**。
- 这是 Mac Metal 观察，不是进程物理内存、iPhone 内存、热或产品延迟预算。

运行前 ComfyUI 队列为空。预检发现共享 `ollama serve` 长期服务进程存在，但 `/api/ps` 为 `{"models":[]}`。原先“不得有 Ollama 进程”的过严条件在模型推理前修正为“不得有已加载 Ollama 模型”；没有停止共享服务，也没有调用 Ollama 推理。原 runner 和 inference plan 副本、修正收据均保留。

## 证据与边界

主证据：`artifacts/verification/f08-smolvlm2-valid36-20261115/`。

- `parent-prepared-verification.json`：36 题、288 帧、36 组像素和模板独立复算通过。
- `smol-metal/result.json`：唯一 Metal 进程终态，14/36、invalid1、峰值和耗时。
- `parent-result-verification.json`：86 份完整 logits/EOS、KV offsets、raw decode、严格评分和保护哈希通过。
- `comparison.json`：与冻结 Qwen3 aggregate 的逐题比较及晋级门失败。
- `preflight-correction.json`：空闲 Ollama 服务边界的推理前修正。

Qwen3 的 16/36 来自此前 iPhone 两进程质量汇总，Smol 本轮来自 Mac Metal；两者共享选择、源帧、问题与评分，但使用各自原生视觉预处理/模板和不同运行平台。这是候选筛选，不是同 tensor、同 runtime 或端到端速度/内存比较。Smol 未达到先验晋级线，因此不再用手机复跑来追平平台。

## 后续裁定

- 停止 Smol2.2B valid36 分支，不重跑、不调 prompt/resize/帧数刷分。
- Qwen3 与 Smol 在独立 valid36 都低于可靠通用视频理解要求；当前问题不是换到 Smol2.2B 即可解决。
- 下一产品方向应先明确一个更窄、可验收的任务合同，或引入有独立质量依据的新模型/训练方案；继续在这两个 2B 4-bit 候选上做同题算子和输入微调，信息增益已经很低。
