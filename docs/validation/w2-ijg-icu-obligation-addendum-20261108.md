## libjpeg-turbo

The retained [LICENSE.md](../../artifacts/verification/f02-dng-notice-delivery-20261106/notice-input/skia/third_party/externals/libjpeg-turbo/LICENSE.md) is expressly an explanatory roll-up, **not itself a license** (`Complying with the libjpeg-turbo Licenses`, lines 25-92). Its license-scope description is at lines 1-23, and the Modified BSD text is at lines 94-135. It describes the IJG terms for the libjpeg API (including inherited and modified code; SIMD zlib terms are subsumed in that API context), and Modified BSD for the TurboJPEG API and build system; a TurboJPEG binary/API also carries the IJG terms because TurboJPEG wraps libjpeg. The binding IJG text is retained in [README.ijg](../../artifacts/verification/f02-dng-notice-delivery-20261106/notice-input/skia/third_party/externals/libjpeg-turbo/README.ijg), `LEGAL ISSUES`, lines 114-162; its specific conditions are lines 136-162.

For source redistribution, IJG requires the unaltered README with its copyright/no-warranty text, clear indication of additions/deletions/changes in accompanying documentation, and acceptance of responsibility for undesirable consequences. For modified libjpeg-turbo source, preserve existing notices, add a copyright notice to each modified source file (or, if it has no copyright header, a notice that it was modified), and include the unaltered IJG README. The Modified BSD conditions additionally retain its copyright/conditions/disclaimer in source and reproduce them in binary documentation/materials; do not use project/contributor names for endorsement. These are conditional on source modification/distribution and on TurboJPEG inclusion/use as specified in LICENSE.md.

For executable-only/binary distribution, README.ijg §2 requires this exact product-documentation acknowledgement:

> This software is based in part on the work of the Independent JPEG Group.

LICENSE.md further says the same applies to binary-only libjpeg-turbo and statically linked applications; if the binary includes or uses TurboJPEG, its documentation must also include the Modified BSD license text. Parent read-only inspection of the existing published-digest-selected `.6` notices JAR verified that `META-INF/ondevice-ai-kit/notices/ATTRIBUTIONS.txt` contains this exact acknowledgement on line 2. That material's declared SHA-256 is `05d945aef9cbd5a844c0dc9857d3e5506ddf1babaa0ac6cf9da48597447ea7b4`; the matching receipt is `artifacts/verification/w2-source-delivery-decision-20261108/ijg-icu-retention-inspection.json`, which identifies the existing notices JAR by SHA-256 `288450e32041441a36a528da34bb69e3f598ba35f7441787a85a175c4e1bbfa9`. The same parent inspection verified that the full LICENSE.md and README.ijg in the JAR match the retained sources and recorded hashes. This bounded exact-acknowledgement/full-text preservation is **verified by the parent**, not by helper tools; it is not a broader compliance or release approval.

## ICU

The retained [full ICU LICENSE](../../artifacts/verification/f02-dng-notice-delivery-20261106/notice-input/skia/third_party/externals/icu/LICENSE) is not just Unicode V3. Unicode V3 permits broad use/distribution if its copyright and permission notice accompanies copies or associated documentation and restricts promotional use of holder names without permission (lines 1-39). It also includes the legacy ICU 1.8.1–57.1 notice (copies and supporting documentation; no unauthorized promotional use; lines 51-84).

The same file includes nested third-party terms: cjdict's Google BSD conditions plus TaBE BSD and IPADIC/NAIST terms (source notice retention, binary documentation, and restrictions on endorsement; the IPADIC text also carries ICOT no-warranty conditions; lines 88-290); Lao word-list terms (lines 294-332); Burmese word-list BSD-style terms (source notice retention and binary documentation; Burmese additionally restricts endorsement; lines 336-374); TZ database material described as public domain (lines 378-399); and Google double-conversion BSD-style notice conditions (lines 403-430). The ICU4C-only `aclocal.m4` section (lines 434-466) and `config.guess` section (lines 469-495) state GPL terms with Autoconf-generated-configuration-script special exceptions; `install-sh` has its own MIT terms (lines 499-512). Those source-only build-script provisions do **not** make the ICU binary copyleft. Which dictionary files or build scripts are actually included or redistributed is not inferred here.

Parent read-only inspection verified that the full 512-line ICU LICENSE in the existing published-digest-selected `.6` notices JAR matches the retained source and recorded SHA-256 `17510cf7a58b4879b887ec05a45d72cf1b73544dd9ec7e72f20110ed104229ee`. The existing `.6` receipts report 74 notice materials and a successful fresh anonymous consumer. This documents text preservation, not proof that every nested component is used or that a notice count alone establishes compliance.
