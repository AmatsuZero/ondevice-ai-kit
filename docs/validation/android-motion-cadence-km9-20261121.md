# KM9：原画直出、EGL 原画、Spatial 的播放节奏

**在这台手机上，播放节奏的波动在原画直出时就存在，Spatial 另有可测的呈现开销。** 固定 60 Hz 后，两个直出场次的「音频主时钟给出的目标 → 视频图层实际呈现」P95 为 16.44、16.10 ms；两场 EGL 原画为 18.31、17.71 ms；两场 Spatial 为 29.80、27.57 ms。Spatial 有 860、872 帧实际增强上屏，但满足媒体时窗和取帧预算两条要求的增强仅 138、151 / 900。保留默认原画、手动 Spatial；下一步先对音频主时钟给每帧排出的目标时刻做对照。观看者可另外用[运动 A/B](android-motion-pairs-km9-20261121.md)判断画质收益。

## 同片、同刷新率的六场结果

TECNO KM9 / API 35 / Mali-G57 MC2，原来同一份 H.264/AAC 960×540、30 fps、900 帧测试片。六场共 5,400 个源帧；每场解码完成、音频位置到达片尾。沿用上一轮的普通调试 APK；原画直出是 MediaCodec 直接送 Surface，另两路都用 EGL 就绪即提交，Spatial 在同帧增强来不及时回退原画。播放顺序如下。两轮的结果是单机重复观测，不代表机型总体。

| 场次 | 路径 | 视频图层确认 / 900 | 命中媒体时窗 | 目标→呈现 P50 / P95（ms） | 相邻源帧间隔约 67 ms 或更长 / 可比较间隔 |
|---|---|---:|---:|---:|---:|
| 12 | 直出 | 896 | 890 | 10.40 / 16.44 | 3 / 891 |
| 13 | EGL 原画 | 893 | 886 | 11.50 / 18.31 | 4 / 885 |
| 14 | Spatial | 898 | 882 | 15.33 / 29.80 | 9 / 895 |
| 15 | Spatial | 897 | 890 | 15.04 / 27.57 | 9 / 893 |
| 16 | EGL 原画 | 881 | 877 | 11.43 / 17.71 | 4 / 877 |
| 17 | 直出 | 896 | 892 | 7.56 / 16.10 | 1 / 892 |

- 「确认」要求本场源帧的请求时刻与视频子图层的期望呈现时间**纳秒精确相同**，并取得有效的实际呈现时间；缺记录不计物理掉帧。媒体时窗是从该帧的音频目标起到目标后 33⅓ ms（不含右端），与以取帧为起点的耗时不同。
- 六场已确认显示间隔的中位数均约 33.33 ms、P95 均约 50 ms。直接统计“大于 50.000 ms”会将接近三个刷新周期的微小抖动计入或排除。表的末列改用最接近的刷新周期数 ≥4，并只比较源帧编号连续的两次确认；这**没有修改**原来的按时验收标准。
- 第 16 场有 896 个应用 EGL 显示记录，其中 881 个也被图层采样捕获，15 个只有 EGL 记录。为保证三路口径一致，表内没有用这些记录补数。四场 EGL 路径共 3,569 个双侧确认，呈现时间逐帧完全一致。直出没有应用 EGL 取帧时间，严格取帧预算不适用。
- Spatial 两场确认的增强/原画回退分别为 860/38、872/25。9/895 和 9/893 个较长间隔是整条 Spatial 播放路径的表现，不能据此断定某一帧因着色器而变慢。
- 片源 PTS 是规则的 30 fps，但应用给相邻源帧排出的目标间隔，在六场中 P95 已达 44.2–46.1 ms。可先在同机对照现有播放头观测与更稳定的音频时间锚点，分别验证目标间隔、直出呈现节奏及音频连续性。现有证据不能给出物理音画同步误差，亦不证明某个时钟实现已是唯一原因。

## 如何获得并复算数据

1. 先验证独立普通调试包与片源的 SHA 与[前轮](android-spatial-playback-km9-20261121.md)一致。每场新建私有 run 目录，以 `SrRunActivity` 的 `original`、`original-ready` 或 `spatial-ready` 模式各播完整片，应用记录源编号、媒体 PTS 与音频目标。固定组前读回系统最大/最小率 120/60，短暂将最大率设为 60；固定组结束后读回恢复为 120/60。六场所采图层周期全部是 16,666,667 ns。
2. 与播放并行，每约 1.35 秒从 `dumpsys SurfaceFlinger --list` 取当前运行 Activity 唯一的 `SurfaceView[包/Activity](BLAST)#编号`，将**图层名本身**作为一个参数传入 `dumpsys SurfaceFlinger --latency`。循环历史三列按 Android 15 AOSP `FrameTracker::dumpStats` 的 desired / actual / ready 顺序解析；等待 fence 的占位值、零和历史重复不算新帧。从应用请求时间精确对应到音频目标及源编号；增强标识另按源编号、代次、EGL frame ID、成功 swap 与正显示记录确认。Perfetto 的 Activity 窗口时间线不能替代这个视频图层。
3. 场 1–11 是探索组，保留原始应用事件和去重后的合成器行；不混入固定组。场 1 的正确图层采样开得晚，只覆盖 127 帧；场 6 中途切换代次并重复给出一个源 PTS，901 个回调，保留为失败。其他探索场中出现过 90 Hz。固定组场 16 播放终态与事件已取回，拉 Perfetto 时 ADB 一度不可用；重新连接后补取 trace，并确认仍为 60 Hz，再执行最后一场。没有用 UI 绘制帧、codec release 或最近时间近似匹配来补齐显示数据。
