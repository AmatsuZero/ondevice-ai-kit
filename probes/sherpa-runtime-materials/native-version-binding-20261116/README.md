# Native version binding evidence

This text-only record covers the three version-return functions in four fixed Sherpa C-API ELF members. The [validation report](../../../docs/validation/w3-native-version-binding-20261116.md) defines the accepted scope and limitations.

- `source-log-binding.json` and `reconstructed-version.cc`: pinned source/patch identity and 38 original retained CI lines.
- `parent-manual-reference-check.json`: manual LLVM operand arithmetic, independent `PT_LOAD` mapping and original-AAR member comparison.
- `*-c-api-version.objdump.stdout`: disassembly, including the rejected default ARM-mode interpretation and corrected explicit Thumb output.
- `candidate-*` and `corrected-unit-tests.stderr`: preserved first candidate and fixture failures.
- `corrected-real-four-abi-green.json`: raw decoder results and eight same-length in-memory negative controls.
- `final-unit-tests.stderr`, `integrated-unit-tests.stderr`, `bounded-review.json` and `parent-acceptance.json`: executed final checks and the supplied-context independent review boundary.
- `hy3-delivery-receipts.json`, `cleanup-receipt.json` and `material-manifest.json`: complete helper termination, exact cleanup and retained text identities.

There are no ELF/AAR or model binaries in this directory. Full prompts, raw events and the original binaries remain in local ignored artifacts. This is static evidence only; forged strings remain possible. It does not establish complete native source identity, full composition, runtime behavior, production adoption or P1–P4/R4/R5/W3 completion.

`diff-check-disposition.json` preserves two original failed-unittest progress-line trailing-space diagnostics; source, docs and all other evidence pass the separate whitespace check. The raw log is not reformatted.
